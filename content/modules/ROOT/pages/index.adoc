== Welcome

In this ~2 hour Zero-Touch lab you will learn Event-Driven Ansible (EDA) on
*Ansible Automation Platform 2.6* by building *one rulebook* and hardening it
until it remediates a cloud misconfiguration and *verifies* the result.

You will:

. Choose a track, clone the lab repo from Gitea, and edit the rulebook in the terminal
. Create Automation Controller and EDA projects, then run a rulebook activation
. Secure intake with *Event Streams*
. Add environment and severity *guardrails*
. Remediate and verify a Floci (AWS emulator) resource for your chosen track

Success is a *verified* cloud outcome and a clear *Rule Audit* trail — not merely
that a job started.

== Choose your track

In Module 1 you run `~/eda-lab/bin/select-track.sh`, which records your choice and
clones the workshop from Gitea. Pick *one* track for the whole lab, or take *all three*
if you want every example. Instructions for each track appear in every module.

[cols="1,3",options="header"]
|===
| Track | Scenario

| *A — S3 public exposure*
| A bucket is exposed to the internet. Your rulebook matches `S3PublicExposure`,
enables Block Public Access (`Remediate - S3 BPA`), and later verifies BPA on Floci.
Simplest path — choose this if you are unsure.

| *B — Open security group*
| A security group allows wide `0.0.0.0/0` ingress. You match `OpenSecurityGroup`,
quarantine or revoke the open rules (`Remediate - SG Quarantine`), and verify the group.

| *C — Runaway instance*
| An instance is running out of policy. You match `RunawayInstance`, stop it with
quarantine tags (`Remediate - Stop Instance`), and verify state and tags on Floci.

| *All three*
| One rulebook with rules for S3, SG, and runaway. You inject and audit each path.
Longer than a single track; use when you want the full set of examples.
|===

== Lab environment

[cols="1,2",options="header"]
|===
| Component | Purpose

| Ansible Automation Platform 2.6
| Controller + Event-Driven Ansible (projects, activations, Event Streams, Job Templates)

| Gitea
| Lab SCM at `{gitea-url}` — clone, edit the rulebook, push; both Controller and EDA projects sync from here

| Floci
| AWS emulator at `{floci-endpoint}` — the API and console run as containers, and all three misconfigurations are pre-seeded

| Terminal
| Track selector, alert injector, and Git clone under `~/eda-lab/`
|===

Pre-built Job Templates (do not rewrite the playbooks — wire them from your rulebook):

* `Remediate - S3 BPA` / `Verify - S3 BPA`
* `Remediate - SG Quarantine` / `Verify - SG Quarantine`
* `Remediate - Stop Instance` / `Verify - Stop Instance`
* `Escalate - Notify` (stretch)

== How Zero-Touch checks work

Each module has *Validate*. Checks use your track marker from Module 1
(`~/eda-lab/track` containing `s3`, `sg`, `ec2`, or `all`).
